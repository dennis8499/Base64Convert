# Base64 檔案轉換工具

使用 .NET 10 與 Windows Forms，將檔案先壓縮，再包裝為 v2 Base64 文字分片，並將分片合併還原。程式以固定緩衝區與暫存檔處理資料，不需要將整個檔案載入記憶體。

自動使用 Brotli 品質 11、視窗 22 壓縮整份檔案，只有包含容器標頭及 Base64 開銷的總輸出嚴格較小時才採用；大小相同或變大時儲存原始資料。原始檔名、大小及 SHA-256 內嵌，還原時一律驗證，不需另外傳送 JSON 檔。

**僅支援 v2 分片。** 舊版分片必須用舊版程式還原，再以新版重新轉換；舊版程式不能讀取新的 `.v2.part…` 分片。

## 執行

需要 Windows 及 [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0)。在已安裝 .NET 10 SDK 的環境中，先建置方案：

```powershell
dotnet build Base64Convert.slnx -m:1 '-bl:.artifacts/build-{}.binlog'
```

啟動程式：

```powershell
dotnet run --no-build --project src/Base64Convert.WinForms
```

執行不依賴額外測試套件的整合測試：

```powershell
dotnet run --no-build --project tests/Base64Convert.Tests
dotnet run --no-build --project tests/Base64Convert.UiSmokeTests
```

## 使用方式

1. 在「轉換與拆分」選取來源及輸出資料夾，設定每片上限後開始轉換。預設為 15 MB，1 MB = 1,000,000 位元組，上限向下對齊 4 位元組。
2. 程式先在背景壓縮及計算 SHA-256，再選擇較小的表示方式並編碼、拆分。完成後顯示實際壓縮方法、原始大小、文字總大小、分片數與節省比例。
3. 傳送同一組的全部文字分片即可。分片檔名為 `<原始名稱>.<12 位十六進位識別碼>.v2.part000001-of000003.txt`；請保留檔名。
4. 在「合併與還原」選取全部分片（順序不限），再選擇儲存位置。程式自動辨識壓縮方式，完整驗證後才替換目的檔案；原始檔名即使在分片名稱中被縮短，也能從內嵌資訊還原。

壓縮、編碼與還原都能取消。關閉視窗會先取消作業並等待清理完成；單次原生壓縮呼叫執行期間，取消可能延後生效。品質 11 對大型、已壓縮或隨機資料可能耗時較長，最終仍可能選擇不壓縮。

## 暫存與失敗處理

匯出需要額外磁碟空間保存壓縮候選檔及全部待提交文字分片；候選壓縮檔未被採用時會先刪除。準備完成及開始輸出時檢查可用空間，實際寫入失敗仍會停止並清理。來源維持唯讀開啟至作業結束。還原則先寫入目的資料夾內的暫存檔，所需額外空間約為原始檔大小。

覆寫前需確認，提交分片時會把既有檔案移到同磁碟備份，失敗時嘗試回復。若回復失敗，程式會保留 `.base64convert-*.tmp` 資料夾並回報完整位置；其中 `backup-000000` 對應第一片、`backup-000001` 對應第二片，依此類推。此時請先保存及復原備份，再刪除暫存資料夾。一般取消、拒絕覆寫或失敗均自動清理；清理失敗會一併回報原始錯誤與保留位置。

「節省比例」以同一 v2 格式未壓縮輸出為基準。容器標頭也占空間，因此小檔可能比舊版純 Base64 稍大。分片上限只適用於文字檔，不含郵件附件再次編碼、郵件標頭或內容。SHA-256 用於完整性檢查，不能證明來源真實性。

## v2 格式與核心 API

全部文字分片依序串接為標準 Base64（ASCII、無 BOM、無換行，僅最後一片可含 `=`）。解碼後的位元組結構為：

```text
8 bytes  ASCII "B64CVT02"
4 bytes  JSON 長度（UInt32、小端序，1～65,536 位元組）
N bytes  UTF-8 JSON（無 BOM）
M bytes  資料內容（原始資料或單一完整 Brotli 串流）
```

JSON 欄位名稱大小寫固定，全部必填：

| 欄位 | 型別／規則 |
|---|---|
| FormatVersion | 整數，固定 2 |
| SetId | 12 位十六進位字串，須與分片檔名一致 |
| OriginalFileName | 安全的原始檔名，不含路徑 |
| OriginalLength | 非負 Int64，解壓縮後的位元組數 |
| PayloadLength | 非負 Int64，資料內容的位元組數；`none` 時與 OriginalLength 相同 |
| Compression | 字串 `none` 或 `brotli` |
| Sha256 | 原始資料的 SHA-256，64 位十六進位字串 |

拒絕未知欄位、版本、演算法、不完整或多餘資料、長度溢位與不安全檔名。標頭可以跨越分片，空檔也會產生含標頭的非空分片。

`CreateExportPlanAsync` 完成準備後回傳 `ExportPlan`；請用 `await using` 管理，即使使用者拒絕輸出也必須釋放。每份計畫只能匯出一次，`ExportAsync` 成功或失敗後均會釋放資源。`ExportResult` 包含原始／資料內容／Base64 大小、未壓縮基準、實際方法及分片數。還原使用 `CreateRestorePlanAsync`、`RestoreAsync`，不接受外部資訊檔。這些是 v2 的介面變更。

## 效能量測

執行以下命令會在各自獨立的處理程序中量測 10 MB／100 MB 重複 CSV、隨機資料及 10 MB ZIP，輸出 JSON 統計。樣本以固定緩衝區產生，並在還原後再次比較雜湊；暫存資料於量測結束後刪除。

```powershell
dotnet run --no-build --project tests/Base64Convert.Tests -- --performance
```

紀錄包含準備、編碼、還原耗時、輸出大小與處理程序峰值工作集。重複 CSV 是高度規律的合成資料，結果不代表一般 CSV；峰值工作集包含執行階段與壓縮器原生記憶體，不等於緩衝區大小。

2026-11-16 本機單次量測（Windows、.NET 10、Debug、十進位 MB；時間為壓縮準備階段）：

| 樣本 | 原始大小 | 最終 Base64 大小 | 採用方式 | 準備時間 | 峰值工作集 |
|---|---:|---:|---|---:|---:|
| 固定重複列 CSV | 10 MB | 1,408 bytes | Brotli | 1.49 秒 | 78.7 MB |
| 固定重複列 CSV | 100 MB | 9,620 bytes | Brotli | 9.35 秒 | 79.5 MB |
| 隨機資料 | 10 MB | 13,333,648 bytes | 不壓縮 | 6.73 秒 | 81.3 MB |
| 隨機資料 | 100 MB | 133,333,648 bytes | 不壓縮 | 91.36 秒 | 82.1 MB |
| 已壓縮隨機資料 ZIP | 約 10 MB | 13,337,876 bytes | 不壓縮 | 11.02 秒 | 83.8 MB |

此表僅為合成樣本的觀測值，不是固定壓縮率、執行時間或記憶體上限的保證。
